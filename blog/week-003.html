WEEK 003 · MARCH 2026 · SYDNEY

The game talks to a database now

Browser game → Supabase → leaderboard. The whole stack is working.

Last week we had a 3D game running in a browser. This week it saves your score to a real database and there's a live leaderboard anyone can see.

// what happened

We connected the Roblox clone to Supabase. When you collect all 8 coins, your username and time get posted to a scores table via the REST API. One fetch call. That's it.

Then we built a leaderboard page that reads the top 10 scores ordered by fastest time. Gold, silver, bronze highlights for the top 3. It pulls live from the database every time you load it.

Browser game → Supabase POST → scores table → leaderboard GET → rendered.
The whole round trip. No backend server. No deploy pipeline. Just static HTML and a database.

The thing that hits different is how little code this took. The Supabase REST API is just fetch with the right headers. No SDK, no npm install, no build step. A single HTML file talks directly to a Postgres database.

// dracenstein studio

Also this week — we started planning out something bigger. Dracenstein Studio — a full asset creation pipeline for building game-ready content from text prompts.

The vision is four studios working together:

  • Character Studio — generate a complete game character from a text prompt. 3D model, animations, voice, AI personality. One prompt, one character.
  • Object Studio — props, weapons, items, furniture. Anything a character can interact with.
  • Environment Studio — terrain, buildings, skyboxes, lighting. Whole worlds from a description.
  • Game Studio — ties it all together. Rules, levels, mechanics, win conditions.

The endgame: type "a medieval blacksmith who speaks with a Scottish accent and gets nervous around horses" and get back a rigged 3D model with idle animations, a voice pack, dialogue trees, and an AI behaviour system. Ready to drop into a game.

We're not there yet. Not even close. But the direction is clear —
collapse the gap between describing something and having it exist.

Week 2 was proving the game works. Week 3 was proving the stack works. Week 4 and beyond — we start building the tools that build the things.
